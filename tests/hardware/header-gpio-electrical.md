| Orange Pi Zero 3W | 6.6.98-vendor-sun60iw2 / `1eb1160f92dd1d566af920002583c67fbbb6eb35d190a62fb8f0bc1236bb74e1` | The same 244 µs request on PD4 changed main-controller IRQ cell 2 to 244000. Both runs listed all 28 physical GPIO contacts. Invalid contacts, unsupported drive-strength settings, foreign IRQ claims, a missing pad helper, conflicts in the same bank and a later overlay overriding the vector were rejected without changing armbianEnv.txt. Compatible per-pin requests shared one bank filter. Removing one requester preserved the other's setting. Rollback restored the original selections, accepted a reordered boot environment and refused unrelated edits. Unit doubles tested live edge/owner flags, missing gpiochips, reversed chip enumeration and identical relative offsets on different controllers.

Both kernel modules were cross-built against the matching distribution headers. Their vermagic and OF aliases were verified after staging the driver packages with depmod. In a QEMU guest using the actual H618 ARM64 kernel and a memory-backed gpiochip, the production driver applied pull-up/down/off and nominal drive settings without selecting direction or changing output levels. The test observed descriptor release, an occupied GPIO returning EBUSY, and an unsupported configuration failing probe. A GPIO v2 client then re-requested a released line, read back a 244 µs line-request attribute on the capable test line, and observed rejection of filtered edges on the fixture line lacking both hardware debounce and an IRQ.

The configurator, framework runtime and mesh packages were built as `0.1~git1436.f0e6bea1`. The extracted configurator composed and verified a Zero 3W profile with 20 mA nominal drive and a 244000 ns bank cell. The repository retains the sources and repeatable checks. Electrical current and pulse timing on silicon are still hardware measurements. [Commands and kernel references](../../hardware/header-gpio/README.md)
