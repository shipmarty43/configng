# Header integration and offline kits, 28 November 2026

| Test target | Installed from the kit | Checked after reboot |
|---|---|---|
| Orange Pi Zero 2W, Resolute XFCE, 6.18.57 | PWM kernel and original rollback, armbian-config-zero2w, wiringpi-orange-gpio, GPIO preset module, I²C recovery and DFR0528 drivers | Selected PWM2/3 through the packaged PWM002 terminal menu at 500 ns. The profile and both pin routes rolled back. On the in-memory I²C adapter, the actual DFR0528 power_supply driver reported 51%, 3,593,750 µV and Unknown charging state. |
| Orange Pi Zero 3W, Trixie Minimal, 6.6.98 | PWM kernel and original rollback, armbian-config-zero2w, wiringpi-orange-gpio, GPIO preset and I²C recovery modules | Selected PWM0/1 at 500 ns in PWM002 and saved fan levels 0/64/128/192/255. Both settings survived reboot and rolled back. The installed Python binding independently drove the main and standby memory-backed gpiochips, rejected an occupied output and released both lines. |

Each clean image completed stock → patched → stock boots under its own ARM64 kernel. dpkg installed from the same offline payload later distributed in the kit. The boot script and distribution DTB were verified throughout. The restored Image was byte-identical to the original, and both backing images kept their initial SHA-256. The test opened a real PTY, selected a saved profile, verified the composed board DT and file contents after boot, then used the saved configuration rollback. The QEMU devices model controller behaviour. Electrical timing, bootloader execution and board-specific wiring are physical acceptance items. [Archives, component versions and SHA-256](evidence/header-kits-2026-11-28.json) · [Installer and test commands](../../packaging/pwm-kernels/README.md)

**I²C and UART.** On both guest kernels the production bridge recovered a simulated SDA release under the adapter lock and propagated busy, timeout and unsupported errors. A Linux PTY returned ENOTTY for RS-485. A driver double filtered the requested polarity in the buffer passed to SET as well as on GET. The tool detected it and verified restoration. Zero 2W DT tests covered the DE route and pin conflicts. On A733 the v100 BSP exposes a separate GPIO direction mode and lacks native RTS direction control. [BUS001](../../hardware/i2c-recovery/README.md)

**SPI.** Two simultaneous native Linux spidev clients in A733 QEMU each exchanged 64 eight-byte messages. The fixture took mode and speed from the actual composed board DT. SPI2 CS0 used 1 MHz, mode 2; SPI3 CS0 used 8 MHz, mode 3. Each response included controller identity, mode, requested clock and caller data. [Register-independent virtual test](a733-spi-twin/run.sh)

**WiringPi.** Host tests verified all 28 A733 header GPIOs, both controller identities, reversed enumeration, invalid layouts and board-specific request guards. The Trixie runtime rejected a library linked against Ubuntu's GLIBC_2.42. The accepted Trixie package was rebuilt against Debian 13, declares a glibc 2.38 floor and ran inside the clean Debian image. The H618 gpio-sim Python and loopback suites also passed with the updated binding. [Library and package build](https://github.com/shipmarty43/WiringPi/blob/e3fd737/python/README.md)

**Web and terminal.** armbian-gui shares OS temperatures, power, fan drive, fresh GNSS and loader state between both interfaces. The web viewer authenticates HTML, API and static assets. A real PTY published its selected profile to the separate web client and released it on exit. The host suite passed 113 tests and seven subtests. Three gpio-sim-only cases were skipped on the host and covered by the separate ARM64 SX1262 suite (17 passed). Zero 2W identification covers the CC1101 and nRF24 registers and PN532 firmware framing over SPI or raw I²C. Unknown wiring and conflicting selections are reported. Physical peripheral transfer and RF qualifications remain open. [Interfaces and access](https://github.com/shipmarty43/armbian-gui/blob/d9442d0/README.md#board-diagnostics-and-the-web-viewer)
