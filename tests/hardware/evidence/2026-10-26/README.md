# Retained board evidence, 2026-10-26

See the [validation report](../../zero2w-validation-2026-10-26.md) and
[development handoff](../../README.md) for setup, commands and limitations.
These are selected observations from the same physical Orange Pi Zero 2W.

| Files | What they support |
|---|---|
| `vulkan-compute*.txt` | Integer compute correctness on Mali-G31 and explicit rejection of a CPU-only ICD |
| `gles-render.txt`, `xfce-panvk-cube.txt` | GLES pixel checks and hardware Vulkan presentation |
| `codec-summary.txt` | Four explicit GStreamer decoder pipelines and frame comparisons |
| `cedrus-vainfo.txt` | Enumerated VA-API profiles, not proof that each profile works |
| `cedrus-vaapi-h264.txt`, `vaapi-media-sha256.txt` | Actual Cedrus H.264 decode, output dimensions/count and matching output hashes |
| `vaapi-repro-smoke.txt` | Repeat execution of the committed VA-API smoke-test script |
| `hardware-pwm1.txt` | Physical 32-to-29 loopback measurements, endpoint levels and cleanup |
| `chromium-browser-trial.txt` | Failed browser-startup trial; no hardware browser playback established |
| `tested-packages.txt` | Installed package versions captured after the experiments |

The original validation workspace path is replaced by `<validation-workspace>`;
the temporary browser debugger ID and transient invocation ID are normalized.
Trailing whitespace in the FFmpeg log is removed.
Raw logs, diagnostic scripts and a snapshot of the pinned external VA-API source
are retained privately off the SD card. Browser profiles and full SD backups are
not part of this public evidence. Synthetic raw frames are regenerated by the
scripts instead of committed. FFmpeg pointer addresses are diagnostic output.

`SHA256SUMS` covers the retained evidence files and test sources relative to this
directory. It detects later changes; it is not an independent test attestation.
Verify from this directory with `sha256sum -c SHA256SUMS`.
